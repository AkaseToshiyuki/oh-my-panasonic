# 硬件兼容性

当前测试版支持 CF-SV7（CFSV7-3L / CF-SV7HD9VS）、BIOS V3.11L22，以及 CF-SR3（CFSR3-1 / CF-SR3SKAKS）、BIOS V1.00L12 和 V1.00L27。测试环境为 Ubuntu 26.04.1、Linux 7.0 和 GNOME 50。升级固件后按型号、完整 SKU 和 BIOS 重新选择硬件后端，保留旧固件支持和已有设置；未知版本仅启用通用控制。

所有机型共用同一版本、主包、面板与服务；安装时自动选择硬件后端。CF-SR3 / i5-1245U 的硬件支持范围如下：

| 功能 | CF-SR3 |
| --- | --- |
| 圆形滚动与动态图标 | Synaptics I²C 06CB:CE53；保留多指手势 |
| 风扇 | 本机 BIOS 标准、静音及散热优先温控点，性能、自定义曲线与手动输出；8 秒失联恢复 |
| CPU | 8/12 W、15/28 W、28/55 W 长/短时上限，以及最高性能 35/55 W 目标；不超过当前处理器与系统上限，不关闭 DPTF |
| 电池 | 电量、充放电功率、容量、循环次数；运行时限充、立刻充满及自动保养；15 秒失联恢复 |
| Type-C | 标准接口初始化成功时显示协商信息；没有实测输入功率 |
| 睡眠、关机限充 | L12、L27 均已实机验证 s2idle 睡眠和关机期间暂停充电；L27 复测约 3 分钟睡眠和 6 分钟关机，全程保持外接电源连接 |

CF-SR3SKAKS / i5-1245U 的 BIOS L12 和 L27 普通启动均读到 28/55 W 的处理器上限，寄存器处于锁定状态。软件预设受此硬件上限约束。最高性能采用 83°C 目标和 85°C 紧急降功耗，退出后恢复原先的风扇选择。

SR3 的 ACPI 风扇状态不返回 RPM。手动输出调用原生 `TFN1._FSL`，EC 返回独立的输出百分比。`SEFM(1)` 表示由操作系统负责主动散热，不等同于 Windows 静音档。软件从本机 `data_vault` 校验并读取 ACPR 温控点，对应机身 SEN3、供电电路 SEN4 和充电器 SEN7；多个温度源的请求取最大值，并加入平滑响应和 CPU 温度保护。性能档同时采用散热优先温控点和 CPU 性能曲线。该实现采用原厂温控点，不代表复现 Windows 全部 DTT 功率仲裁和时序。专有热管理表不随软件分发。

服务停止、超时、睡眠或温度达到 85°C 时交还固件自动散热。手动输出与自定义曲线保留。仅自定义图可编辑；SV7 的标准、静音档仍由固件管理，固件没有公开预设曲线时显示“固件自动”，不绘制推测曲线。

| 功能 | 支持范围 |
| --- | --- |
| EC 电池、风扇与光驱 | 限白名单型号及 BIOS；主包自动安装匹配的 DKMS 模块。电池控制还校验完整 SKU |
| 圆形触控板 | CF-SV7 的 SynPS/2 Synaptics TouchPad，以及 CF-SR3 的 Synaptics I²C 06CB:CE53 |
| CPU 功率与温度 | 取决于内核提供的 RAPL、温度和性能计数接口 |
| SSD 电源状态 | ZHITAI TiPlus5000 1TB / ZTA10666、SilverMake 2268XT2 B58R 1TB / X0430M00 支持 PS0、PS1、PS2，保留 APST；其他型号仅使用可用的通用空闲接口 |
| 状态栏 | GNOME 50 |
| Wi-Fi | NetworkManager 管理的可见、隐藏个人网络；企业证书认证进入系统设置 |
| 蓝牙 | BlueZ 扫描、配对、连接、断开和移除；不同实体外设的兼容性可能不同 |
| 显示 | Mutter 提供的实际分辨率、刷新率与缩放；复杂多屏排列进入系统设置 |
| 人脸 | 兼容 Facelock、红外摄像头和模型；UHD 620 / Iris Xe 共用可选核显组件，编译缓存与本机硬件匹配 |

SR3 最高性能使用 83°C 调节目标和 85°C 降功耗保护。35/55 W 是预设目标；L12、L27 普通启动的处理器上限仍为 28/55 W。安装本包本身不改启动配置；可选启动守卫需通过 `sudo pou-boot-power enable --apply` 显式启用。面板与状态栏分别显示当前系统限制及处理器限制。L12 临时提高硬件上限后的浮点对照中，35 W 相对 28 W 的吞吐量提高约 4.6%，38/40 W 的额外提升不足 0.4%。L27 的 28/35/28 W 对照中，35 W 档稳定实测约 32.9 W，吞吐量提高约 5.4%，最高温度 78°C；该轮使用 Type-C 与电池辅助供电，不能据此判断充电器可以独立维持该负载。这些短时测试不代表所有应用的收益或长期稳定性。

启动守卫仅支持上述完整 SKU、i5-1245U 和 L12/L27，要求 Secure Boot 当前已关闭。它保留原 Ubuntu 启动入口和功耗锁，保存本机原始配置，只更改经过验证的 PL1 与 cTDP 字段。首次启用会自动重启一次；以后每次启动需由电源、电池和温控服务确认健康，未确认则下一次启动恢复原字段并重启。恢复程序要求机器能完成开机自检并运行守卫，不能替代硬件刷写恢复。原值备份仅保存在本机，升级 BIOS 前应先关闭守卫并完成恢复。

`sudo pou-boot-power disable --apply` 安排恢复；重启完成后核对 `pou-boot-power status` 和处理器上限，再卸载或更新固件。启动配置处于启用状态时卸载会被阻止，软件升级保留状态。启动守卫及服务通过 11 项虚拟机失败回退场景和单元测试，L27 实机首次启用及再次普通重启均读回 35/55W 并通过服务健康确认，最高性能档在空闲切换检查中正确获得 35W 上限，结束后原设置完整恢复。L12 的一次性修改与恢复曾实机通过，自动守卫尚未在 L12 实机重复验证。此可选功能默认关闭。

无线使用 Ubuntu 原始驱动。SR3 睡眠日志偶有 AX211 DMA 读访问被 IOMMU 拦截及复位超时，已观察的挂起后网络可自行恢复，尚未发现持续使用故障。本包不替换无线模块、不关闭 IOMMU；相关内核告警保留，等待发行版上游修复。

风扇曲线从当前 BIOS 读取，旧固件与新固件各自使用原有温控点。L27 的标准曲线调整了供电电路温度对应的输出，静音和散热优先曲线与 L12 相同；用户自定义曲线、响应时间和手动控制继续保留。

## 可显示的电源数据

电池放电功率、CPU 封装功率、平台能量计和 Type-C 协商功率是不同指标。平台能量计不覆盖所有外围设备，也不是充电接口电表。

CF-SV7 可读取 PD 协商电压、电流和功率上限，目前没有可信的 Type-C 实际输入电压、电流或功率测量接口。风扇 RPM、电池循环次数和其他读数仅在硬件返回有效值时显示；固件反馈百分比不能换算成可信 RPM。

CF-SR3 枚举出 PAC1934 电源监测通道，但目前尚未确定外接电源总输入对应的电流通道，不能把各局部通道相加作为整机输入功率。Linux 7.0.0-43 在 UCSI 初始化失败后读取 `debugfs` 的 `avg_current` 会触发内核空指针异常；不要使用这些调试节点测量电源。正常监控仅使用已初始化的标准接口。

电池温度支持标准电池接口及已验证的 CF-SV7 固件接口。当前 CF-SR3 未提供标准温度读数，固件映射尚未验证，因此隐藏该项。

CF-SV7 开机充电需要至少 27 W 的 USB-C 电源输出，关机充电需要至少 15 W，见[松下 SV7 开发者访谈](https://news.mynavi.jp/article/20180216-sv7/2)。充电器额定功率不等于当前端口协商功率；多口功率分配、转接设备和协议支持都可能影响可用档位。未充电且协商功率低于要求时，面板显示“PD 供电不足，等待充电”。

SSD 的最大工作功率是设备公布的规格，不代表当前耗电；更低的电源状态可能增加访问延迟。实际续航取决于工作负载和设备。

## 充电与休眠

SV7 与 SR3 运行时支持指定充电上限，保养模式下可在睡眠或关机期间暂停充电；各固件的验证状态见上表。已完成的离线限充测试均保持外接电源连接，未验证关机期间拔插适配器后的行为。SV7 验证的睡眠模式为 deep，SR3 为 s2idle。此功能不能在关机后从低电量充到任意用户目标再自动停止。需要完整充电时，先在面板选择“立刻充满”。

电池维护仅在满足供电、电量和负载条件时进行；预计可用时间属于估计值。低电量关机等系统保护仍由 Ubuntu 管理。

其他机型、实体光盘、多显示器和外设组合尚未全部验证。请保留密码登录；人脸认证未经过独立的大样本误识率与攻击评估。
